## Task-Card Handoff Gate

The solution has been confirmed, but `方案 OK` does not create a task-card
handoff. The host must encode structured handoff evidence in a typed proposal.

### Direct execution

An explicit same-session modification instruction such as `开改`, `按这个改`, or
`开始实现` authorizes host-native `direct-edit`. Do not compile a task card.
Independent protected-path, release, external-write, credential, migration,
destructive-operation, review, and verification boundaries still apply.

### Explicit task-card handoff

Generate a task card only after an explicit handoff instruction such as:

- `生成任务卡`
- `按这个方案出任务卡`
- `给我你执行的任务卡`

The solution/diagnosis, scope, verification, and handoff boundaries must also be
provided as a typed `HandoffContract` with explicit `task_level`. Request governance/compiler blocks card output when:

- the instruction is missing: `block_reason: task_card_not_requested`
- the confirmed contract is missing: `block_reason: handoff_contract_not_confirmed`

The compiler gate protects handoff artifact generation. It is not a prerequisite
for authorized direct local execution.

### Host Plan-mode finalization

When the host is in Plan mode, do not create a separate final-plan document.
Keep exploring and resolving decisions without mutation until the contract is
decision-complete. Then:

1. Compile the final artifact with
   `ags task compile --host-plan-mode-final --confirmed-handoff-contract`.
2. The artifact itself is the canonical `## 任务卡`.
3. If the host requires `<proposed_plan>`, use it only as the UI envelope around
   the exact card.
4. The Plan UI keeps the exact card pending activation.
5. Selecting Execute switches the host to Default/execution mode and dispatches
   the unchanged card plus `task_card_hash`; the execution Agent validates it
   first and never regenerates it.

`--host-plan-mode-final` replaces the separate task-card-request prompt. It does
not replace the confirmed contract gate and does not itself authorize mutation.

### Existing task cards

If the first non-empty line is `## 任务卡`, validate it as an existing handoff
contract. Valid cards skip generation and continue to policy/gate/LaunchPlan; invalid
cards fail closed.

### Handoff sequence

1. Confirm solution/diagnosis, scope, verification, and handoff boundaries.
2. Receive an explicit task-card/handoff instruction, or reach the final
   decision-complete host Plan-mode artifact.
3. Pass both structured gates.
4. Classify Light/Medium/Heavy from the confirmed contract.
5. Generate the canonical task card.
6. Validate, resolve policy, and prepare a LaunchPlan; the host owns dispatch.
