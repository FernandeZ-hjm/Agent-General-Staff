## AGS Delivery Report Closure

Produce the final delivery report as one copyable Markdown fenced block. Use an
outer four-backtick `markdown` fence and add no prose outside it.

````markdown
# 任务交付报告

Closure schema: 1.1
Contract ID: <exact task-card Contract ID>
task-card-hash: <exact LaunchPlan task_card_hash>
launch-plan-hash: <exact LaunchPlan launch_plan_hash>
execution-mode-used: plan-only | single-writer | fanout-in-card | fanout-cross-card
execution-topology-used: single | parallel | worktree
delegation-used: none | in-card | cross-card

状态: completed | partial | blocked
review-gate: pending-review | passed | n/a

一句话结论：<summary>

## 目标闭环
- G-01: done | partial | skipped — <result or reason>

## 验收闭环
- AC-01: pass | fail | not-run — evidence: <command result or artifact>

## 验证闭环
- V-01: pass | fail | not-run — <exact check and result>

## 改动与边界
- changed: <file and summary>
- untouched: <non-goal or protected boundary>
- subtasks: used: <how> | not-used: <reason>

## 未闭环项
- none

## 风险与下一步
- 风险：无 | <risk>
- 下一步：无 | <action>

## Evolver / GEP
- planning recall：yes | no | skipped
- recall path：MCP | CLI | skill fallback | unavailable
- recall state：status=... / search=... / fetch=...
- used gene/capsule：none | summary-only | <id>
- adoption impact：none | scoped design decision | avoided approach | risk flag
- outcome recorded：yes | no | pending
- record target：method | gene | capsule | none
- reason if skipped：<reason>
````

### Requirements:

- Preserve every `G-*`, `AC-*`, and `V-*` from the task card exactly once.
- `completed` requires all goals done, acceptance criteria and verification
  items passed, review closed, and `未闭环项` equal to `none`.
- `partial` or `blocked` must list the exact set of non-closed `G-*`, `AC-*`,
  `V-*` IDs (plus `review-gate` when pending), each with a reason; missing,
  extra, duplicate, or free-form rows fail closure.
- Save the report, then run
  `ags task close <task-card> <launch-plan> <delivery-report> \
  --receipt-out <receipt.json> --format json`.
- The Rust closure kernel derives the receipt ID and writes the receipt. Do not
  calculate hashes or generate receipts in the host adapter.
- Do not claim completion or archive the receipt unless closure validation
  returns `valid: true`.
